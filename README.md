# NS-Monitior

Дисплей Nightscout для **LilyGO T-Display S3** и **M5Stack CoreS3 / CoreS3 SE**.
Показывает глюкозу и тренд, работает как часы и предупреждает звуком о выходе
за пороги. Обе модели используют общее веб-меню настройки с телефона,
получают пороги тревог из Nightscout и обмениваются паузой Snooze по локальной Wi-Fi сети.

## Возможности

- Основной экран: крупная глюкоза, стрелка тренда, изменение значения, возраст
  измерения, время, IOB, COB и заряд Blueberry или помпы на выбор.
- Экран часов: крупное время, дата, день недели и информация о глюкозе.
- Цвет показаний по настроенным границам: зелёный, жёлтый или красный.
- Загрузка четырёх порогов и флагов тревог из Nightscout при запуске и затем
  каждые 5 минут; после ошибки — повторная попытка через 30 секунд.
- Общие веб-настройки T-Display S3 и CoreS3 / CoreS3 SE: серверные пороги,
  включение типов тревог, громкость, Wi-Fi, время и источник батареи.
- Сохранение нескольких сетей Wi-Fi и параметров Nightscout.
- Яркость **100 → 70 → 30 → 10 → 1%**, с сохранением выбранного уровня.
- Звуковые тревоги, громкость 0–100%, проверочный сигнал и выбор длительности паузы.
- Общая пауза Snooze 30/60/90/120 минут и отмена между устройствами в одной
  локальной сети с одинаковым адресом Nightscout.
- Раздельные двойные стрелки тренда на основном экране и часах, без полного
  оборота при изменении только количества стрелок.
- Журнал событий для проверки подключения и работы устройства.

При запуске отображается журнал до первого успешного ответа Nightscout.
При временных ошибках сети остаётся последнее успешное показание;
данные старше 15 минут заменяются прочерками. Значок батареи показывает заряд
**Blueberry или помпы** на обеих моделях дисплея. Источник выбирается в веб-настройках
в поле «Источник заряда батареи на экране». Нажмите **«Сохранить и выйти»**;
выбор сохранится после перезагрузки. По умолчанию выбран Blueberry.
Если Nightscout не передаёт корректные проценты выбранного источника, отображается `--%`.

## Цвета элементов дисплея

### Глюкоза и зоны

Цвет крупных цифр глюкозы определяется четырьмя границами из настроек.
В таблице они обозначены как **Г1 < Г2 < Г3 < Г4**; значение глюкозы — **G**.

| Цвет | Условие |
| --- | --- |
| Красный | G ≤ Г1 или G ≥ Г4 |
| Жёлтый на T-Display, оранжевый на CoreS3 | Г1 < G ≤ Г2 или Г3 ≤ G < Г4 |
| Зелёный | Г2 < G < Г3 |
| Серый | Нет корректного значения или данные устарели |

В настройках по умолчанию границы — **3,9 / 4,5 / 8,5 / 10,0 ммоль/л**.
После успешной загрузки Nightscout используются серверные значения.
Для заводских границ 3,9 и 10,0 отображаются красным, 4,5 и 8,5 — цветом
предупреждения своей модели платы. В веб-меню обеих плат жёлтые зоны шкалы
порогов имеют чистый жёлтый цвет **`#FFFF00`**.

### Основной экран

| Элемент | Поведение цвета |
| --- | --- |
| Крупная глюкоза | Цвет зоны из таблицы выше |
| Изменение глюкозы (дельта) | Зелёный при росте больше 0,05 ммоль/л, красный при падении больше 0,05 ммоль/л по модулю; в пределах ±0,05 — светло-серый |
| Стрелка тренда | Голубая; направление и количество стрелок обозначают тренд |
| Возраст измерения | Зелёный текст; сам цвет этой надписи не меняется с возрастом |
| Время, IOB и COB | Светло-серые |
| Заряд выбранного источника: значок и проценты | 0–15% — красные, 16–35% — оранжевые, выше 35% — салатовые; неизвестный заряд — серый |

Цвет дельты означает направление изменения, а не принадлежность к безопасной зоне.
При потере данных соответствующие числовые поля заменяются прочерками.
На основном экране цвет глюкозы не приглушается постепенно по мере старения данных.

Двойные тренды `DoubleUp` / `DoubleDown` показываются двумя раздельными стрелками
на основном экране и экране часов. Поворот выполняется всей группой; при смене
только количества стрелок направление сохраняется без полного оборота.
Масштаб ограничивает рисунок областью стрелок, включая промежуточные кадры и тройные тренды.

### Экран часов

Время, глюкоза, дельта, возраст измерения и стрелки используют **общий цвет зоны глюкозы**.
В отличие от основного экрана, дельта здесь не получает отдельный цвет по направлению изменения.
Дата и день недели остаются светло-серыми.

Цвет также учитывает возраст измерения:

- При отображаемом возрасте **0–5 минут** используется обычный цвет зоны.
- Начиная с **6 полных минут** цвет приглушается смешиванием с серым.
- При неизвестном возрасте цвет сильнее приглушён; устаревшие или отсутствующие
  значения отображаются серыми прочерками. Сами часы продолжают показывать время.

Проверка устаревания чисел выполняется по секундам: с возраста **15 минут**
основные данные заменяются прочерками, хотя надпись возраста показывает только полные минуты.

### Звук, подсветка и журнал

| Элемент | Цвет и значение |
| --- | --- |
| Значок звука T-Display | Зелёный — звук включён и данные моложе 10 минут; серый — нет свежих данных или достоверного времени измерения; жёлто-оранжевый — обычная тревога; красный — критическая тревога; красный перечёркнутый и таймер — Snooze; красное предупреждение — ошибка звука |
| Кнопка тревоги CoreS3 | Зелёный — звук включён при свежих данных; красный — отсрочка, тревога или ошибка звука; жёлтый — нет свежих данных без активной тревоги |
| Индикация при выключенной тревоге | Скрыта на обеих моделях |
| Всплывающая яркость | Белые цифры на синем фоне |
| Журнал | Информация — зелёная, предупреждения — жёлтые, ошибки — красные |

Сообщения прошивки в журнале и Serial выводятся только на английском.
Экран журнала использует компактный шрифт Montserrat 12. Коды HTTP, GPIO
и имена полей Nightscout сохранены для диагностики.

Серый значок динамика T-Display появляется при возрасте измерения 10 минут или
больше, до первого успешного измерения либо при неизвестной/будущей метке времени.
При активной тревоге подсветка временно повышается до максимума.

## Первое подключение и настройки

1. При первом запуске устройство открывает экран настройки. На уже настроенном
   устройстве откройте его кнопкой, указанной ниже для вашей модели.
2. Подключите телефон к Wi-Fi устройства по большому QR-коду либо введите
   показанные на экране имя сети и пароль.
3. Откройте предложенное телефоном окно входа в сеть. Если оно не появилось,
   отсканируйте малый QR-код или откройте **http://192.168.4.1/** в браузере.
4. Укажите домашнюю сеть Wi-Fi, адрес Nightscout и часовой пояс. На обеих платах
   нажмите **«Загрузить настройки из Nightscout»**: после чтения сервера
   появятся четыре серверных порога, включение типов тревог и громкость.
   Snooze использует общий цикл 30/60/90/120 минут/OFF; базовый интервал задаётся в `app_constants.h`.
5. Нажмите **«Сохранить и выйти»**. Устройство перезагрузится с новыми настройками.

Кнопка **«Проверить сигнал»** воспроизводит два коротких писка с выбранной громкостью,
даже если тревога выключена или действует отсрочка. Частота зуммера T-Display
фиксирована: **2000 Гц** для тревоги и теста. Настройки частоты в веб-интерфейсе нет.
Тест не сохраняет громкость и не сбрасывает отсрочку; после него возвращаются
сохранённые параметры тревоги. Громкость сохраняется кнопкой «Сохранить и выйти».
При громкости 0% проверка проходит без звука.
На T-Display S3 громкость пассивного GPIO-зуммера регулируется долей активного уровня PWM:
линейная шкала задаёт её от 0 до 50%. 0% полностью отключает LEDC,
30% соответствуют заполнению около 15%, 50% — 25%, 100% — 50%.
Для тишины в паузах LEDC отсоединяется, а GPIO возвращается к уровню отключения;
это не ослабляет сам сигнал. Сохранённая громкость после прошивки остаётся прежней.
Акустическая громкость зависит от частоты и излучателя; проценты не означают дБ.
У активного GPIO-зуммера со встроенным генератором доступны выключение и включение.
На обеих платах портал работает в режиме AP+STA: получение данных Nightscout,
обновление серверных порогов и обмен Snooze по LAN продолжаются в настройках.

## Управление LilyGO T-Display S3

Две физические кнопки, горизонтальный экран. Для звуковой тревоги требуется
подключённый пассивный buzzer.

| Кнопка | Короткое нажатие | Удержание |
| --- | --- | --- |
| Верхняя, GPIO14 | Сразу включить/переключить Snooze | Переключить основной экран и часы |
| Нижняя, GPIO0 (BOOT) | Изменить яркость | Открыть настройки |
| Обе одновременно | В журнале — вернуться на предыдущий экран | Открыть журнал |

Удержание одной кнопки распознаётся примерно через 0,6 секунды.
В журнале отдельные кнопки прокручивают записи; удержание продолжает прокрутку.
На экране настроек удержание верхней кнопки перезагружает устройство для выхода.

Слева по центру основного экрана и часов расположен индикатор звука:

- Зелёный значок — тревоги включены, данные свежие; серый — нет свежих данных.
- Оранжевый значок — обычная тревога, красный — критическая.
- Красный перечёркнутый значок — общая пауза Snooze; под ним оставшееся время
  в минутах и секундах, для сроков от 100 минут — минуты с округлением вверх.
- Если тревога выключена в настройках, значок и таймер скрыты.

## Управление M5Stack CoreS3 / CoreS3 SE

Сенсорный горизонтальный экран и встроенный динамик для тревоги.

| Действие | Результат |
| --- | --- |
| Короткое нажатие POWER | Изменить яркость |
| Двойное нажатие POWER | Открыть журнал; повторное — вернуться |
| Удержание POWER около секунды | Открыть настройки |
| Свайп влево или вправо | Переключить основной экран и часы |
| Свайп вверх в журнале | Перейти к более новым записям |
| Свайп вниз в журнале | Перейти к более старым записям |
| Касание нижней экранной кнопки | Отсрочка тревоги |
| Нажатие RST | Перезагрузить устройство |

Короткое нажатие POWER срабатывает с небольшой задержкой для распознавания двойного.
После открытия настроек отпустите POWER: более долгое удержание может выключить питание.
В настройках работают изменение яркости и вызов журнала; свайпы отключены.

Нижняя экранная кнопка показывает состояние тревоги и отсрочку с обратным отсчётом
в минутах и секундах. При выключенной тревоге кнопка скрыта.
Касание этой кнопки не запускает свайп.

## Настройки и тревоги Nightscout — обе платы

Четыре порога загружаются из `/api/v1/status.json`:
`settings.thresholds.bgLow`, `bgTargetBottom`, `bgTargetTop`, `bgHigh`.
Nightscout хранит эти значения в mg/dl даже при отображении mmol/L;
прошивка переводит их в ммоль/л. Загружаются также `alarmUrgentLow`, `alarmLow`,
`alarmHigh`, `alarmUrgentHigh` и соответствующие массивы `*Mins`, с резервными
`alarmUrgentMins` / `alarmWarnMins`. Настройки и привязка к серверу сохраняются
в NVS (`nsAlarms`); пороги сохраняются вместе с существующими границами.

T-Display S3 и CoreS3 / CoreS3 SE используют одно меню и одну логику загрузки.
Пороги загружаются при запуске и затем каждые 5 минут при доступном сервере;
после ошибки загрузки повторяются через 30 секунд, когда клиент измерений свободен.
Устройства с одним сервером получают одинаковые пороги независимо от модели платы.
При временной потере сети используются последние сохранённые границы.
Пороги не передаются напрямую по LAN: общий источник — Nightscout.

При открытии веб-настроек обеих плат разделы порогов глюкозы и звуковых тревог скрыты.
Оба появляются после нажатия «Загрузить настройки из Nightscout» и успешного чтения
сервера. Фоновая загрузка до открытия страницы и сохранённый флаг NVS `loaded`
не раскрывают разделы. При изменении адреса или токена разделы снова скрываются;
нужно повторно нажать «Загрузить». Границы отображаются из снимка
сервера и не редактируются локально. Четыре флага типов тревог можно переопределить
для устройства либо следовать включению с сервера. Это переопределение не блокирует
обновление границ. Серверные массивы интервалов сохраняются для совместимости
настроек NVS; управление Snooze использует общий локальный цикл, описанный ниже.

**Ограничение записи порогов:** в Nightscout 15.0.8 `status.json` предоставляет
параметры `BG_LOW`, `BG_TARGET_BOTTOM`, `BG_TARGET_TOP`, `BG_HIGH` только для чтения.
Штатного REST API для их изменения нет; API профиля изменяет профиль терапии,
а не эти четыре параметра запуска. Для их изменения на Jino нужна панель хостинга,
затем повторное подключение в портале устройства. Изменённые пороги из старой формы
отклоняются с HTTP 409 до записи NVS; локальное сохранение не имитирует обновление
сервера. Автоматическая запись потребует документированного API хостинга или
реализованного серверного расширения. Такого расширения прошивка не предполагает.
Кнопка подключения проверяет текущие поля формы; постоянное сохранение выполняет
«Сохранить и выйти». Громкость сохраняется отдельно, 0% отключает звук.

Звук включается **только в красной зоне**: глюкоза `≤ bgLow` или `≥ bgHigh`,
включая сами границы, как при выборе цвета на дисплее. Жёлтая и зелёная зоны
не вызывают звуковую тревогу. На T-Display S3 в красной зоне критический тип вызывает
три коротких писка с более частым повтором; если этот тип выключен, разрешённый обычный
тип той же стороны вызывает два писка. Частота зуммера T-Display — 2000 Гц.
На CoreS3 встроенный динамик воспроизводит два коротких сигнала 1800 Гц для любого
разрешённого типа тревоги. Сервер Nightscout сохраняет собственные условия тревог.
Звук возможен только при корректном значении
и возрасте измерения **меньше 10 минут**. Неизвестные/будущие метки и устаревшие
данные не вызывают звуковую тревогу; при отсутствии NTP используется время сервера.
Визуальное скрытие устаревших чисел по-прежнему происходит через 15 минут.

## Snooze — обе платы

Поведение соответствует [M5_NightscoutMon](https://github.com/mlukasek/M5_NightscoutMon#buttons):
GPIO14 на T-Display или нижняя экранная кнопка CoreS3 **сразу** включает общую
паузу звуковых тревог. Её можно включить заранее, при нормальной глюкозе,
без интернета и до загрузки настроек сервера, если звук включён в настройках.
Быстрые нажатия с интервалом **меньше 2 секунд** переключают
**30 → 60 → 90 → 120 минут → OFF → 30…**. Каждое нажатие отсчитывает выбранную
длительность заново от текущего момента. После интервала **2 секунды или больше**
нажатие начинает цикл с 30 минут. OFF отменяет действующую паузу немедленно;
звук возобновляется, если условие тревоги сохраняется. Пауза общая для обычных
и критических тревог на обеих платах.
При смене экрана пауза продолжается. Перезапуск сбрасывает локальный таймер.
Красный индикатор и обратный отсчёт показывают действующую паузу.

Устройства в одной Wi-Fi подсети с одинаковым адресом Nightscout обмениваются
паузой и отменой через UDP broadcast, порт **50555**. Поддерживается формат
оригинала `M5_Nightscout SNOOZE: USR=<CRC16>, SnoozeUntil=<Unix seconds>`:
CRC16/MODBUS с начальным значением 0 от адреса Nightscout, время в UTC.
Для совместимости значение `nightscout` в M5NS.INI должно точно совпадать
с сохранённым адресом этого устройства (обычно имя хоста без `https://` и `/`).
Команда отправляется сразу при нажатии, трижды с интервалом 250 мс.
Передаётся абсолютное время окончания паузы: каждый получатель рассчитывает
оставшееся время и запускает собственный таймер по `millis()`.
Отмена передаёт `SnoozeUntil=0`. Подтверждения доставки нет;
полученные команды не пересылаются обратно.
Другой адрес Nightscout, повреждённый пакет или срок больше суток игнорируются.
Смена адреса Nightscout сбрасывает паузу прежнего пользователя.

Для передачи и приёма срока нужны синхронизированные часы (NTP либо время
Nightscout на обеих платах); локальная пауза работает по `millis()` даже без них.
OFF передаётся и принимается без часов. Потеря Wi-Fi не останавливает локальный
таймер. Обмен требует доступного broadcast между устройствами: гостевая изоляция
и разные подсети могут его блокировать. Поздно подключившееся устройство не
запрашивает уже действующую паузу; следующее нажатие снова передаст состояние.
Snooze не отправляет ACK или devicestatus в Nightscout, не меняет паузу браузера
и не требует прав токена на запись. Старые серверные документы Snooze не читаются.

Пороги сверены с официальными исходниками Nightscout, commit
`92d0834219aa771b5837dbcbf1baeb839a200cf6`:
[нормализация порогов](https://github.com/nightscout/cgm-remote-monitor/blob/92d0834219aa771b5837dbcbf1baeb839a200cf6/lib/settings.js).

DNS/TCP/TLS/HTTP обслуживает одна задача FreeRTOS (`NightscoutSession`),
LVGL получает копии результатов через очередь. Подключение Wi-Fi поэтапное;
обработчики кнопок и портала не ждут ответа сервера. Перезапуск после веб-запроса
отложен по `millis()`, без `delay()`. Журнал защищён от одновременной записи задач.

## Звук и подсветка — CoreS3

CoreS3 использует серверные пороги и флаги типов тревог, как T-Display S3.
Общий звук по умолчанию выключен; громкость сохраняется отдельно.
0% отключает звук, но не условие тревоги. Звуковое предупреждение об отсутствии
данных через 15 минут заменено общей логикой: звучат только разрешённые типы
тревог красной зоны по данным моложе 10 минут. Устаревшие числа скрываются через
15 минут, а кнопка сообщает об отсутствии свежих данных.

При тревоге повторяются два коротких сигнала с паузой около четырёх секунд.
Подсветка временно становится **100%**, даже при громкости 0%. После прекращения
тревоги или включения отсрочки возвращается выбранная яркость. Если изменить яркость
во время тревоги, новый уровень применится после её завершения.
Проверка звука сама по себе подсветку не повышает.

Кнопка отсрочки перебирает значения:

**30 → 60 → 90 → 120 минут → отмена.**

Нажатия с интервалом меньше 2 секунд переходят к следующему значению.
Через 2 секунды или больше выбор начинается с 30 минут.
Срок отсчитывается заново от нажатия, а не прибавляется к остатку;
пауза и её отмена передаются по LAN, как описано выше.

Отсрочка общая для всех типов тревог и сохраняется при временном выходе из красной зоны.
После её окончания или отмены звук возобновится, если условие тревоги сохраняется.
Перезапуск и выключение тревоги в настройках сбрасывают отсрочку.

Повторный ответ сервера с тем же измерением не делает его свежим.

## Для разработчиков

### Константы поведения

Общие параметры собраны в [src/app_constants.h](src/app_constants.h).
Каждая группа снабжена комментариями на русском: назначение, единицы измерения,
ограничения и влияние на работу. Значения при переносе сохранены.

| Что изменить | Константы |
| --- | --- |
| Размер истории и длину сообщения | `log_capacity`, `log_message_bytes` |
| Количество строк и частоту обновления журнала | `log_visible_rows`, `log_refresh_ms` |
| Частоту запросов и возраст для повторного опроса | `poll_interval_ms`, `poll_stale_seconds` |
| Срок скрытия устаревших показаний | `data_expiry_seconds` |
| Начало приглушения цвета часов | `fresh_age_minutes` |
| Ступени отсрочки и окно быстрых нажатий | `snooze_step_minutes`, `snooze_steps`, `snooze_restart_ms` |
| Частоту в прошивке, длительность писка и паузы | `buzzer_frequency_hz` (GPIO13: 2000 Гц), `alarm_frequency_hz` (CoreS3), `alarm_beep_ms`, `alarm_second_beep_ms`, `alarm_repeat_ms` |
| Тип GPIO-зуммера и уровень отключения | `buzzer_active`, `buzzer_module_input`, `buzzer_inactive_high` |
| Длительность теста сигнала | `sound_test_ms` |
| Подключение Wi-Fi и повторы Nightscout | Группы `wifi_*`, `http_*`, `ns_retry_*`, `host_error_backoff_ms` |
| Имена устройств и точки доступа | `wifi_*_hostname`, `portal_ssid` |
| Антидребезг, удержание и повтор кнопок | `button_*`, `cores3_double_click_ms` |
| Ступени яркости и время её индикации | `brightness_levels`, `brightness_overlay_ms` |
| Серверы времени и период синхронизации | `ntp_primary`, `ntp_secondary`, `ntp_resync_seconds` |
| Заводские границы, громкость, яркость и часовой пояс | `default_*` |

Например, `log_capacity = 200` увеличит историю до 200 записей; расход RAM
вырастет примерно пропорционально. `log_message_bytes` включает завершающий ноль,
а русские буквы в UTF-8 занимают несколько байтов. `log_visible_rows` задаёт
число строк интерфейса отдельно от объёма хранимой истории.

Отсрочка рассчитывается как шаг × номер ступени. При шаге 15 и четырёх ступенях
получится 15/30/45/60 минут и отмена. Подсказки в веб-настройках получают список
из прошивки. Интервалы звука считаются между началами писков, поэтому при
длительности 180 мс и интервале 360 мс тишина между двумя писками составляет 180 мс.

После изменения констант нужно пересобрать и прошить устройство. Сохранённые
настройки NVS имеют приоритет над `default_*`: изменение заводской громкости
не перезапишет уже выбранную пользователем. Для применения новых заводских
значений можно изменить настройки через портал или выполнить заводской сброс.
При изменении временных порогов обновите также пользовательское описание в README;
существующие тесты проверяют исходное поведение 30/60/90/120 и пороги опроса.

Распиновка остаётся в `include/board_config.h`, параметры библиотеки LVGL —
в `include/lv_conf.h`, геометрия экранов — в файлах `ui_*`. Аппаратные параметры
дисплейной шины остаются в драйверах `src/gfx`.

### Сборка и прошивка

По умолчанию выбрано окружение **`lilygo-t-display-s3`** для подключённой платы
**LilyGO T-Display S3**. В терминале PlatformIO:

```powershell
pio run -e lilygo-t-display-s3
pio run -e lilygo-t-display-s3 -t upload
```

Для **M5Stack CoreS3 / CoreS3 SE** сохранено отдельное окружение `m5cores3` с
профилем `board = m5stack-cores3`. Установленные M5Unified/M5GFX автоматически
различают CoreS3 и CoreS3 SE; драйверы дисплея, тача и подсветки у них общие:

```powershell
pio run -e m5cores3
pio run -e m5cores3 -t upload
```

Для Quad PSRAM CoreS3 SE задано `board_build.arduino.memory_type = qio_qspi`.

### Обновление Nightscout

Первый запрос выполняется при запуске. В жёлтой и красной зонах плановые запросы
выполняются раз в 60 секунд, даже если SGV ещё свежее или его временная метка не изменилась.
Точные границы зон учитываются. В зелёной зоне запрос выполняется, когда возраст
измерения превышает 5 минут 5 секунд; между плановыми запросами проходит не менее минуты.
Интервал отсчитывается от фактического начала последней попытки запроса.

Полученный ответ сразу обновляет экран, включая заряд выбранного источника, IOB и COB.
Отдельный таймер 15 секунд обновляет отображаемый возраст данных и время.
Повторные попытки после сетевых ошибок обрабатываются отдельно. В портале обеих плат
запросы продолжаются через AP+STA.

Источник батареи хранится в NVS в ключе `batterySource`: 0 — Blueberry
(`pump.uploader.battery`), 1 — помпа (`pump.pump.battery.percent`). Если ключ отсутствует
или некорректен, используется `default_battery_source` из `app_constants.h` — Blueberry.
Например, при `pump.pump.battery.percent = 0` и `pump.uploader.battery = 80`
при выборе Blueberry на экране будет **80%**, а при выборе помпы — **0%**. Поле
`pump.pump.battery.voltage` — отдельное напряжение; в проценты оно не переводится.
Отсутствующие или некорректные проценты выбранного источника дают `--%`,
без автоматического переключения на другой источник.


### Оборудование и исходники

T-Display S3: дисплей 320 × 170, кнопки GPIO14 и GPIO0, пассивный трёхконтактный
модуль MH-FMD на GPIO13 с входом active LOW (HIGH — выключен), VCC подключён к
3V3 платы, GND общий. В предоставленном описании модуля указан транзистор 9012.
Звук вынесен в `src/buzzer.h/.cpp`: фиксированные 2000 Гц, писк 180 мс.
Максимальная громкость задаёт 50% времени активного уровня; меньшие уровни уменьшают его долю.
Шкала PWM линейная, без дополнительного квадратичного ослабления; максимум
при 100% составляет 512 из 1024 тактов. Это настройка формы сигнала, а не
калиброванная акустическая громкость.
`buzzer::setVolume()` передаёт выбранный уровень в PWM и при 0 полностью отключает
LEDC с возвратом GPIO к HIGH. Изменение громкости в паузе не включает PWM.
В Arduino-ESP32 2.0.17 звук использует канал LEDC 2 / таймер 1, подсветка — канал 7 /
таймер 3. Подсветкой управляет только `Backlight`, без дополнительного `analogWrite()`.
В коде предусмотрен API 3.x: `ledcAttachChannel` с явным каналом, `ledcWriteTone`,
`ledcWrite`, `ledcDetach`; для 2.x используются `ledcSetup` / `ledcAttachPin` /
`ledcDetachPin` и операции по номеру канала. В новых 3.x одинаковые частоты могут
делить таймер; различие фиксированных частот проверяется при компиляции.
Описание API: [Espressif LEDC](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html).

GPIO13 переводится в обычный выход с уровнем HIGH в начале `setup()`.
Дополнительные меры против щелчков убраны: удержание GPIO, инверсия GPIO-матрицы,
внутренние подтяжки и ранний обработчик `initVariant()`. Для входа active LOW
доля активного уровня пересчитывается в длительность HIGH обычного PWM.
LEDC подключается только на время писка. После каждого писка, отмены тревоги,
отсрочки и перед программным перезапуском LEDC отсоединяется,
GPIO возвращается к уровню покоя HIGH. Начало работы,
смена экранов и подключение Wi-Fi не запускают звук. Тревога и явный тест звука
остаются единственными источниками сигнала.

Длительности и паузы определяются через `millis()` с учётом переполнения.
Отдельная задача FreeRTOS обслуживает последовательность независимо от блокирующих
HTTP-запросов Nightscout; при отсутствии сигнала она ждёт команду. `delay()` и
`esp_timer` для зуммера не используются. Завершение писка имеет точность периода
обслуживания задачи — обычно около 2 мс. `buzzer::play(250)` воспроизводит
одиночный сигнал 250 мс / 2000 Гц; `buzzer::stop()` немедленно отключает его.
Через `buzzer::Config` можно также задать длительность и интервалы тревоги.
Частота не передаётся через веб-запросы и не читается из NVS; ранее сохранённое
значение игнорируется. Частота встроенного динамика CoreS3 задаётся отдельно
через `alarm_frequency_hz`.

Аппаратные параметры в `app_constants.h`:

| Подключение к GPIO13 | `buzzer_active` | `buzzer_module_input` | `buzzer_inactive_high` |
| --- | --- | --- | --- |
| Пассивный двухконтактный, второй контакт GND | `false` | `false` | `false` |
| Пассивный трёхконтактный модуль с входом active LOW (установлен) | `false` | `true` | `true` |
| Активный трёхконтактный модуль с входом active LOW | `true` | `true` | `true` |
| Активный трёхконтактный модуль с входом active HIGH | `true` | `true` | `false` |

Активный зуммер включается логическим уровнем на заданный срок без LEDC; его частоту
определяет встроенный генератор. Постоянный HIGH для пассивного двухконтактного
излучателя к GND запрещён проверкой конфигурации. На CoreS3 GPIO13 уже используется
как I2S-выход встроенного динамика M5Unified, поэтому этот модуль обслуживает только
T-Display S3. У Waveshare GPIO13 занят QSPI-дисплеем. Для T-Display нужно собирать и
прошивать окружение `lilygo-t-display-s3`; окружение `m5cores3` управляет встроенным
динамиком и не создаёт сигнал LEDC для внешнего зуммера.

У пассивного зуммера нет встроенного генератора звуковой частоты, поэтому ему
нужна прямоугольная волна. Наличие входного транзистора не делает его активным;
9012 и S8550 относятся к PNP, а тип зуммера определяется самим излучателем.
В описании установленного модуля указан диапазон питания 3,3–5 В и частот 2–5 кГц.

Если в модуле PNP-транзистор включён эмиттером к VCC, а GPIO управляет его базой
через резистор, при VCC=5 В уровень HIGH=3,3 В от ESP32 может не закрывать его.
Это возможное объяснение гула и тихого сигнала, а не подтверждённый диагноз без
проверки схемы конкретного модуля. Для такой схемы питание от 3V3 позволяет
согласовать уровни; при питании от 5 В нужен соответствующий драйвер управления.
См. [даташит PNP 9012](https://www.onsemi.com/download/data-sheet/pdf/ss9012-d.pdf)
и [пример другого варианта MH-FMD с S8550](https://naylampmechatronics.com/audio-sonido/251-modulo-buzzer-pasivo-mh-fmd.html).

После исправления питания проверьте тест звука на нескольких уровнях громкости.
У пассивного излучателя громкость зависит также от резонанса и duty; шкала PWM
не гарантирует линейного изменения слышимой громкости. В этой прошивке для
GPIO-зуммера используются фиксированные 2000 Гц (`buzzer_frequency_hz`).
См. [влияние частоты и duty на пьезоизлучатель](https://www.murata.com/en-eu/support/faqs/sound/sounder/char/sch0006).

Если после прошивки шум сохраняется при неактивной тревоге, проверьте полярность
входа модуля, общий GND, помехи питания от Wi-Fi/подсветки, длинные провода и утечку
через входной транзистор модуля. До выполнения прошивки (ROM, reset, загрузчик)
уровень обеспечивает внешняя подтяжка к неактивному уровню, обычно 10 кОм: к GND
для LOW или к 3,3 В для HIGH. Токовый излучатель следует включать через подходящий
транзисторный драйвер; при шуме самого модуля может потребоваться отключение его
питания ключом и развязка питания. Саму акустическую тишину нужно проверить на плате.

CoreS3/SE: дисплей 320 × 240; нижние 44 пикселя зарезервированы для управления тревогой.
M5Unified обслуживает дисплей, сенсор, POWER и динамик. Подсветка имеет аппаратные
ступени; проценты задают управляющий уровень, а не измеренную светимость.
Камера, микрофон, IMU и аппаратные часы в приложении не используются.

- `src/main.cpp` — запуск, основной цикл и обработка кнопок.
- `src/ui_*.cpp`, `src/ui_*.h` — экраны и навигация.
- `src/fonts/`, `include/fonts.h` — шрифты и объявления.
- `src/gfx/` — драйверы плат и связь с LVGL.
- `src/alarm_state.h`, `src/backlight.*` — тревоги, отсрочка и подсветка.
- `src/snooze_lan.*`, `src/snooze_protocol.h` — синхронизация Snooze по LAN, совместимая с M5_NightscoutMon.
- `src/buzzer.*` — GPIO-зуммер, безопасное отключение и последовательности сигналов.
- `src/nightscout_client.*`, `src/nightscout_poll.h` — запросы и расписание опроса.
- `src/nightscout_session.*`, `src/nightscout_alarm_state.h` — общая задача сети и настройки тревог обеих плат.
- `src/wifi_manager.*`, `src/captive_portal.*` — Wi-Fi и веб-настройки.
- `src/settings.*`, `src/logs.*` — хранение настроек и журнал.
- `include/board_config.h`, `include/lv_conf.h` — конфигурация плат и LVGL.
- `test/`, `scripts/` — проверки логики и дополнительные шаги сборки.

Настройки хранятся в NVS. При миграции общая тревога включается, если ранее было
включено хотя бы одно из двух отдельных условий.
Красная зона включает первую и четвёртую границы; вторая и третья входят в жёлтую.
Зелёная зона — строго между второй и третьей границами.
На обеих платах звуковые тревоги используют свежесть менее 10 минут и серверные
флаги типов тревог. Общая пауза Snooze обеих плат синхронизируется по LAN.

На обеих платах синхронные операции HTTP/HTTPS вынесены из цикла LVGL в задачу сети.
Окружение `esp32s3-devkit` для Waveshare оставлено как заготовка и не входит в
проверяемые сборки. Поддерживаемые окружения — T-Display S3 и M5CoreS3.

### Проверки

Логические тесты выполняются через `static_assert` без подключённого устройства:

```powershell
& "$env:USERPROFILE\.platformio\packages\toolchain-xtensa-esp32s3\bin\xtensa-esp32s3-elf-g++.exe" -std=gnu++14 -Wall -Wextra -Werror -fsyntax-only -Isrc test/test_alarm_state.cpp test/test_nightscout_poll.cpp test/test_nightscout_alarms.cpp test/test_snooze_protocol.cpp test/test_buzzer_volume.cpp test/test_battery_source.cpp test/test_trend_arrows.cpp
```

Тест веб-настроек проверяет встроенный JavaScript портала, загрузку порогов,
сохранение локальных флагов тревог и отклонение устаревших ответов:

```powershell
node test/test_captive_portal.js
```

Проверочная сборка обеих поддерживаемых плат:

```powershell
pio run -e lilygo-t-display-s3 -e m5cores3
```

прямой адрес и QR-код доступны на экране настройки.

Локальные ZIP-бэкапы находятся в `backups/` и исключены из Git. История исходников
хранится в репозитории; файлы `.bak` из рабочего проекта удалены.
